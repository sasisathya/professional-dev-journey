## 💡 Pro Tips for Success

### Problem Solving
1. **Read carefully** - Understand what's being asked
2. **Ask clarifying questions** - Edge cases? Constraints?
3. **Explain approach** - Before coding, explain your logic
4. **Code clean** - Readability > cleverness
5. **Test edge cases** - Empty array, single element, duplicates
6. **Verify complexity** - Time and space analysis mandatory
7. **Try optimizations** - Once correct, optimize

### Learning
1. **Struggle first** - 10+ min of thinking before solution
2. **Understand deeply** - Why this approach, not just how
3. **Connect patterns** - How is this like previous pattern?
4. **Teach others** - Explain to friend or record video
5. **Solve variants** - If easy, try harder version
6. **Code from memory** - Don't reference solution mid-coding

### Speed & Accuracy
1. **Time yourself** - Build speed gradually
2. **Track metrics** - Accuracy per pattern
3. **Identify weaknesses** - Spend extra time on weak patterns
4. **Do timed drills** - 5 easy problems in 50 min
5. **Mock interviews** - Full 2-hour sessions weekly

## ⚠️ Common Mistakes to Avoid

1. **Skipping patterns** - Even "obvious" patterns → do all 10 problems
2. **Rushing** - 3 problems/week is better than 20 problems/week of garbage
3. **Not analyzing** - Always understand: Why did it work? Could I optimize?
4. **Ignoring complexity** - Complexity analysis is 40% of the interview
5. **Copying solutions** - Read solution ONLY if you try 15+ min first
6. **Not doing mocks** - Mocks are how you learn timing and pressure
7. **Weak area avoidance** - Spend MORE time on difficult patterns
8. **Solo coding only** - Explain your approach out loud while coding
9. **Perfect is enemy of done** - 70% accuracy is better than 0% completion
10. **No breaks** - Burnout is real, take at least 1 day off/week

## 🚨 When You're Stuck

### Stuck on a problem for 15+ minutes?
1. Re-read the problem carefully
2. Identify what data structure you need
3. Think of similar problems you've solved
4. Write pseudocode (no syntax)
5. Then implement
6. Only if still stuck: look at hint (not solution)

### Stuck on a pattern (multiple problems failing)?
1. Review the pattern concept again
2. Do the first 2-3 problems of the pattern together
3. Slow down - 1 problem/day instead of 3/day
4. Watch someone solve it (YouTube)
5. Don't move to next pattern until 80%+ on this one

### Stuck on timeline (falling behind)?
1. Compress by 20% (less time per problem)
2. Skip the hardest variant of each pattern
3. Extend schedule by 2-4 weeks
4. Focus only on most-common patterns
5. Talk to mentor/peer for advice
